# 文档生成规则（RT）

> **所属域**: 规范域 | **加载策略**: 按需加载
> **版本**: 2.0.0 | **创建日期**: 2026-08-06
> **适用项目**: RT（Kotlin Multiplatform）

规定 RT 项目所有文档（规范、技能、方案、需求、CI 等）的生成前检查、生成规则、影响范围评估与实施流程，保证文档体系一致、可维护。

---

## 1. 文档 5 域说明

RT 文档统一按 **5 个域** 管理，每个文档头部必须带「域标签 + 加载策略」：

| 域 | 职责边界 | 典型文档 | 存放位置 | 加载策略 |
|----|---------|---------|---------|---------|
| **核心域** | Agent 行为准则、用户记忆、任务进度 | AGENTS.md、AGENT_RULES.md、MEMORY.md、PLAN.md | `docs/` | 必加载 |
| **规范域** | 开发规范、文档生成规范、命名、构建、Git | PROJECT_STRUCTURE.md、GIT_CONVENTION.md、DOCUMENT_GENERATION_RULES.md | `docs/` | 按需加载 |
| **知识域** | 技术实现细节、模块职责、技能参考 | `*.SKILL.md`、`DOMAIN.md` | `docs/skills/`、模块根目录 | 按需加载 |
| **管理域** | 迁移计划、优化方案、需求跟踪 | 迁移方案、优化方案、需求文档 | `docs/migration/`、`docs/optimize/`、`docs/future/` | 按需加载 |
| **运维域** | 环境搭建、CI/CD、新人上手 | GETTING_STARTED.md、CI 配置 | `docs/ops/` | 按需加载 |

### 1.1 域标签格式（强制，放文档头部第二行）

```
> **所属域**: 规范域 | **加载策略**: 按需加载
```

## 2. 每类文档生成规则

### 2.1 知识域

#### DOMAIN.md（模块职责）
- 放置位置：模块根目录（如 `feature/home/DOMAIN.md`）。
- 内容：模块职责、边界、对外 API/契约、依赖关系、与其他模块交互。
- 更新：模块职责或契约变化时同步更新。

#### SKILL.md（技能文档）
- 放置位置：`docs/skills/`，命名 `<技术>-SKILL.md`（如 `kotlin-SKILL.md`）。
- 内容：适用场景、核心知识点、常见坑、代码示例、验证方式。
- 触发：有明确技术主题、可被 Agent 按需检索的技能即建。

### 2.2 管理域

#### 迁移方案
- 放置位置：`docs/migration/`，命名 `<目标>-migration-plan.md`。
- 内容：迁移背景与目标、现状分析、迁移步骤、风险与回滚、验收标准。

#### 优化方案
- 放置位置：`docs/optimize/`，命名 `<目标>-optimize-plan.md`。
- 内容：优化点、量化指标、方案设计、实施步骤、验收。

#### 需求文档
- 放置位置：`docs/future/`。
- 内容：需求背景、范围、验收标准、关联模块、优先级。

### 2.3 运维域
- 环境搭建 / CI/CD / 新人上手文档，放置 `docs/ops/`（如 GETTING_STARTED.md）。

## 3. 影响范围评估（6 维度 × 3 等级）

任何文档新增/修改前，需从 6 个维度评估影响，按 3 个等级（低/中/高）判定：

| 维度 | 低 | 中 | 高 |
|------|----|----|----|
| 模块影响 | 单文件/单模块 | 2~3 个模块 | 跨全部模块/壳 |
| 构建影响 | 无构建变化 | 新增依赖/脚本 | 变更 AGP/Kotlin/SDK |
| 兼容性 | 完全向下兼容 | 向后兼容需适配 | 破坏性变更（Breaking） |
| 用户影响 | 无可见变化 | 少量交互变化 | 行为/数据迁移 |
| 性能影响 | 可忽略 | 局部可测 | 全链路耗时/内存 |
| 时间成本 | ≤ 1 天 | 1~3 天 | > 3 天 |

- **高影响**：必须先出方案文档、评审后实施。
- **中影响**：评估后小步实施并验证。
- **低影响**：直接实施。

---

## 4. 实施流程（6 步）

```
1. 识别需求     → 明确文档类型与所属域
2. 影响评估     → 按 6 维度 × 3 等级打分
3. 生成文档     → 遵循对应类型模板 + 域标签
4. 交叉校验     → 关联文档（AGENTS.md 速查、PROJECT_STRUCTURE.md 目录）同步
5. 落地验证     → 文件就位、标签规范、引用链接有效
6. 记录归档     → 更新 PLAN.md / MEMORY.md 相关进度
```

---

## 5. 格式规范

- 使用 **Markdown**，中文撰写，标题层级清晰，涉及列举用表格。
- 文件命名 **kebab-case**：技能 `*-SKILL.md`，方案 `*-plan.md`，普通文档 `*.md`。
- 文档头部必须带「所属域 + 加载策略」标签（第 2 行）。
- 头部建议含：版本号、创建日期、适用项目/模块。
- 涉及代码示例需与 RT 技术栈一致（KMP / Compose / Ktorfit / SQLDelight / MMKV / Koin / kermit / Coil / kotlinx-serialization）。
